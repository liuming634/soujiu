# auto 模块开发约束（模块 = 函数 API，flow 负责编排）

> 本文档是 `auto/` 框架的架构契约——想在框架上加功能或移植到别的项目，
> 模块的写法、线程归属、参数与数据约定照此办。

定位：`auto/` 下所有模块按本约束开发；每个模块对外就是一组函数
接口，flow 模块（总调度，`auto/flow/main.py`：监视线程 + while 大
循环三层 if 分发）只通过这些接口调用模块能力、把流程串起来。
模块单独开发、单独测试，flow 统一拼装。架构与方法说明另见
[自动抓取技术实现.md](自动抓取技术实现.md)与
[扩展功能技术路线.md](扩展功能技术路线.md)。

## 核心约束

1. **模块只做函数 API**：对外形态 = "输入参数 → 处理 → return
   数据"的函数。flow 不重复实现模块内部逻辑，模块也不掺和流程
   编排（不切状态机、不改计数、不决定分支走向）。
2. **不自行起业务线程**：模块里不做常驻服务、import 时不启动任何
   线程。持续处理这类物理上必须线程的（actuator 串口接收、landing
   的 IMU 落地监视），把线程封装成 start/stop 函数 API
   （`start_receiving` / `stop_receiving`、`start_landing_monitor` /
   `stop_landing_monitor`），**启动权在 flow**——不调用就一个线程
   都不跑。
3. **纯函数优先，只 return 不入库**：工具型 API（识别、判定、评分）
   返回数据即止，不写 RuntimeData、不存队列；数据怎么存由调用方
   决定。例外：actuator 接收线程、landing 的 IMU 监视线程按各自
   API 的本职约定写入 RuntimeData（接收队列 / 落地判定结果）。
4. **flow 是唯一编排者**：切状态机、改计数、决定分支与回跳、把各
   模块 API 串起来——只在 flow 做；平级模块之间不互相调用
   （例外：scoring 复用 detection 的色块工具判球主色、复用 region
   的抓取圈换算 grab_circle，均为工具级复用，已在各自 `__init__.py`
   注明）。
5. **判定输出三态**：`True` / `False` / `None`（None = 数据缺失
   无法判定），沿用项目既有约定。
6. **时间戳打进数据对象**：跨线程传递的数据（回传帧、IMU）自带
   `time` 字段，接收线程入队前打上，多线程处理按它对齐时序；
   解析/构造函数本身不打戳，保持纯净。
7. **参数不写死**：阈值/范围/权重/时间周期/颜色区间统一放
   `auto/params.py`（auto 模块专用参数文件，按模块分段，调参只改
   这一个文件，不动逻辑代码）；手动链路参数仍在 common 的 config。
8. **接口先行**：先定函数签名与出入参（模块 `__init__.py` 写明
   职责），实现可以后补；接口清单以模块分工为准。

## 当前 API 一览（随实现进度更新）

| 模块 | API | 说明 |
|------|-----|------|
| actuator | `open_comm()` | 按 config 打开下位机串口 |
| actuator | `start_receiving(comm, data)` / `stop_receiving()` | 持续接收线程（内部实现），数据进 RuntimeData 两条队列 + 最新镜像 |
| actuator | `judge_grabber(state)` → 'empty'/'ball'/'cube'/None | 抓取机构实时状况判定（抓取舵机角度查三状况角度范围：静止/抓球/抓魔方，范围参数在 auto/params.py 占位待标定）；状态监视线程全程轮询写 RuntimeData.auto_grabber_status |
| detection | `detect(frame)` → (魔方列表, 球列表, 盆, 桶) | 单 YOLO 模型四类标签；魔方/球列表存 bbox+中点，盆/桶取最高置信度单例 |
| detection | `find_color_blobs(frame, color)` / `dominant_color(frame, bbox)` | 六色色块：球颜色 / 桶底颜色（颜色↔桶映射，路径见扩展功能技术路线.md）共用 |
| region | `grab_circle(w, h)` / `point_in_range(x, y, frame)` / `overlap_px(roi, frame)` / `overlap_ok(roi, frame)` / `filter_grabbable(objects, frame)` | 抓取圈对比板查色（缓存复用）：圈换算 / 点在圈内 / 重合像素数 / 盆可投阈值判定 / 圈内过滤；比例沿用 common config，阈值在 auto/params.py |
| scoring | `score_cubes(cubes, frame, all_cubes=None)` / `score_balls(balls, frame, all_cubes=None)` | 距离+密集 / 距离+颜色+密集 加权评分，返回 ScoredTarget 排序列表（最高分先抓，并列编号序）；密集邻居 = 魔方全部目标（**含抓取圈外**，C1 口径密集只算魔方，score_balls 也传 all_cubes，缺省只数圈内候选）；权重与分值在 auto/params.py |
| landing | `check_imu_impact(current, previous)` | IMU 跳变判定（触地冲击，层1 并列备选源）：相邻两帧差值落区间，任一轴命中即 True，参数在 auto/params.py |
| landing | `check_frame_still(prev_frame, curr_frame)` | 前后帧光流画面静止判定（Farneback，不用 YOLO）：平均幅值落区间 |
| landing | `check_receiver_lost(last_signal_time)` | 接收机失联判定：超时收不到遥控器信号即 True |
| landing | `start_landing_monitor(data)` / `stop_landing_monitor()` | IMU 落地监视线程：imu_queue 新帧逐帧判定，结果写 RuntimeData（只读队列不消费） |
| flow | `start_flow(data, with_camera=False)` / `stop_flow()` | 全部监视线程 + while 大循环装配（STM32 接收 / 接收机判飞行 / 机构监视 / YOLO 任务判定 / 相机取帧 / 大循环三层 if 分发）；任务记账与计数只在 flow 内做 |

## RuntimeData 数据约定

- **接收队列**（actuator 接收线程写入，处理端消费）：
  `actuator_queue`(16) / `imu_queue`(128)，满丢最旧、保留最新。
- **识别结果队列**（调用方按帧放入，非接收线程写）：
  `cube_queue` / `ball_queue`(16)，每项 = 一帧推理的该品类目标列表
  （RoiTarget），供 M 帧防抖、评分取用。
- **最新镜像**：`actuator_state` / `imu_state`，取最新值直接读。
- **状态位**：`auto_flight_state` / `auto_mech_state`（两层状态，
  常量 AUTO_FLYING / AUTO_LANDED、MECH_IDLE / MECH_HOLD /
  MECH_PROCESS 在 runtime_data.py）——层1/层2 监视线程**直改**，大
  循环只读；两层组合 = 六情况覆盖任务全程（见自动抓取技术实现.md）。
  早期单字段 `auto_state`（含 `set_auto_state()`）保留兼容，新代码
  不再用。`auto_grabbed` 已抓物品标记（None/cube/ball，
  flow 写：抓取成功 = 本轮品类，投放完成清空）——与实时判定
  互相独立，"飞行中掉落 = 标记还在 + 实时判定变空爪"。
- **任务记账**（大循环写读，内存即用即清）：`yolo_task`（YOLO 任务
  判定线程直改，四任务类别）、`task_memo` / `task_memo_time`
  （指令已发待验证）、`N / cube_done / ball_done / parity_flip`
  （计数与奇偶翻转）、`grab_fail_cnt / process_handled`。
- **抓取机构实时状况**：`auto_grabber_status`（'cube' / 'ball' /
  'empty' / None，常量 GRABBER_* 在 runtime_data.py），状态监视线程
  按 actuator 的 `judge_grabber` 全程判定刷新——掉落事件 = 上刻
  夹着 + 本刻空爪，组合处理在 flow。
- **落地判定结果**（landing 监视线程 / 调用方写，flow 确认窗取用）：
  `landing_imu_hit` / `landing_imu_hit_time`（IMU 跳变判定及命中
  时刻）、`landing_frame_still`（光流画面静止）、`receiver_last_time`
  （接收机最近信号时刻，读数接入后刷新）。
- 时间戳都在数据对象自己的 `time` 字段里，RuntimeData 不另存时间
  （例外：`receiver_last_time` 本身就是时刻——接收机帧格式待定，
  还没有数据对象可挂，先独立存）。
