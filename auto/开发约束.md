# auto 模块开发约束（模块 = 函数 API，flow 负责编排）

定位：`auto/` 下所有模块按本约束开发；每个模块对外就是一组函数
接口，后面的 flow 模块（主循环 + 状态机 + 计数装置 + 全局监视，
设计稿见 `flow/伪代码.md`）只通过这些接口调用模块能力、把流程串
起来。模块单独开发、单独测试，flow 阶段统一拼装。

## 核心约束

1. **模块只做函数 API**：对外形态 = "输入参数 → 处理 → return
   数据"的函数。flow 不重复实现模块内部逻辑，模块也不掺和流程
   编排（不切状态机、不改计数、不决定分支走向）。
2. **不自行起业务线程**：模块里不做常驻服务、import 时不启动任何
   线程。持续收串口这类物理上必须线程的（actuator 接收），把线程
   封装成 start/stop 函数 API（`start_receiving` / `stop_receiving`），
   **启动权在 flow**——不调用就一个线程都不跑。
3. **纯函数优先，只 return 不入库**：工具型 API（识别、判定、评分）
   返回数据即止，不写 RuntimeData、不存队列；数据怎么存由调用方
   决定。例外：actuator 接收线程写入 RuntimeData 接收队列，这是
   该 API 的本职约定。
4. **flow 是唯一编排者**：切状态机、改计数、决定分支与回跳、把各
   模块 API 串起来——只在 flow 做；平级模块之间不互相调用
   （例外：scoring 颜色因子复用 detection 的色块工具，已在各自
   `__init__.py` 注明）。
5. **判定输出三态**：`True` / `False` / `None`（None = 数据缺失
   无法判定），沿用项目既有约定。
6. **时间戳打进数据对象**：跨线程传递的数据（回传帧、IMU）自带
   `time` 字段，接收线程入队前打上，多线程处理按它对齐时序；
   解析/构造函数本身不打戳，保持纯净。
7. **参数不写死**：阈值/范围/权重/时间周期/颜色区间 → config 或
   模块头部常量集中可调，现场标定只改数值不改代码逻辑。
8. **接口先行**：先定函数签名与出入参（模块 `__init__.py` 写明
   职责），实现可以后补；接口清单的依据是伪代码定稿各阶段"涉及
   模块"的分工（`伪代码.md` §2.4 / §4.4 / §6.4）。

## 当前 API 一览（随实现进度更新）

| 模块 | API | 说明 |
|------|-----|------|
| actuator | `open_comm()` | 按 config 打开下位机串口 |
| actuator | `start_receiving(comm, data)` / `stop_receiving()` | 持续接收线程（内部实现），数据进 RuntimeData 两条队列 + 最新镜像 |
| detection | `detect(frame)` → (魔方列表, 球列表, 盆, 桶) | 单 YOLO 模型四类标签；魔方/球列表存 bbox+中点，盆/桶取最高置信度单例 |
| detection | `find_color_blobs(frame, color)` / `dominant_color(frame, bbox)` | 六色色块：球颜色 / 桶底颜色（§6.7）共用 |
| region | 待实现 | 抓取圈换算 / 点在圈内 / 重合面积 / 圈内过滤 |
| scoring | 待实现 | 距离 + 颜色 + 密集 三因子评分 |
| landing | 待实现 | 冲击触发 + 多源短确认（阶段一确认引擎） |
| flow | 待实现 | 主循环 + 状态机 + FlowCounter + 全局监视（唯一编排者） |

## RuntimeData 数据约定

- **接收队列**（actuator 接收线程写入，处理端消费）：
  `actuator_queue`(16) / `imu_queue`(128)，满丢最旧、保留最新。
- **识别结果队列**（调用方按帧放入，非接收线程写）：
  `cube_queue` / `ball_queue`(16)，每项 = 一帧推理的该品类目标列表
  （RoiTarget），供 M 帧防抖、评分取用。
- **最新镜像**：`actuator_state` / `imu_state`，取最新值直接读。
- 时间戳都在数据对象自己的 `time` 字段里，RuntimeData 不另存时间。
